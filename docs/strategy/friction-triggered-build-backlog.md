# Friction-Triggered Build Backlog

This is the build-later list for the 90-day solo agency rollout.

Rule: do not build these because they sound useful. Build them only when real sales or delivery friction proves they are the bottleneck.

## Build Later

| Item | Build When This Friction Appears | Current Path Before Build |
|---|---|---|
| Cold email setup | Contact forms or DMs are limiting volume, replies, or tracking after the first proof batch. | Use contact forms or DMs. Configure email only with a real physical postal address and confirmed DKIM selector. |
| Intake form | The first paid sprint reveals repeated intake questions, missing assets, unclear approvals, or too much manual collection. | Use the client brain and kickoff flow manually. |
| Background agents | Weekly client work has repeated monitoring or production tasks that are stable enough to run without constant founder intervention. | Keep production prepared by the Growth Brain and reviewed by the operator. |
| Hard-wired model router | Paid delivery shows enough real task volume to justify routing routine, specialist, utility, and manual work through fixed lanes. | Use the Model And Task Routing Standard as the manual operating rule. |
| Public case-study pages | A real external client approves sanitized proof, a result, and a quote or usable case-study signal. | Use owned-product proof only as delivery proof, not paid-client proof. |

## Do Not Build Before

- 5 Loom audits are recorded.
- 5 real sends happen through contact forms or DMs.
- Market learning is run after the first send/follow-up batch.
- At least one paid sprint or concrete sales objection exposes a repeated friction.

## Review Cadence

Review this backlog after each weekly market learning or paid sprint delivery review.

Only promote an item from backlog to build when the evidence answers:

- What exactly slowed sales or delivery?
- How many times did it happen?
- What manual workaround is currently used?
- What would the smallest useful build remove?
- What proof will show the build worked?

## Allowed Before Friction

Pre-revenue diagram parity may define report-only background pool jobs and model-routing packets. It must not run unattended client delivery, auto-send, auto-approve claims, auto-publish, or create live model-spend routing until the friction above exists.
